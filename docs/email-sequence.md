# メールシーケンス仕様

## 概要

リードがフォーム送信した後、自動的にメールシーケンスを実行する。
MVPでは管理画面から手動トリガーまたは Cron で日次バッチ送信。

## シーケンス定義

| ステップ | Day | テンプレートキー | 件名 | 目的 |
|----------|-----|-----------------|------|------|
| 1 | 0 | day_0_thanks | 無料診断のお申し込みありがとうございます | 関係構築・信頼獲得 |
| 2 | 2 | day_2_challenges | バックオフィスでよくある3つの課題 | 課題認識の強化 |
| 3 | 5 | day_5_case_study | 導入事例：月20時間の業務削減に成功 | 具体的イメージ |
| 4 | 8 | day_8_plans | お客様に最適なプランのご案内 | 具体的提案 |
| 5 | 12 | day_12_booking | 無料相談のご案内 | アクション促進 |
| 6 | 16 | day_16_reminder | まだ間に合います：無料相談のご案内 | リマインド |
| 7 | 21 | day_21_final | 最後のご案内 | 最終アプローチ |

## 送信条件

- opt_out が false であること
- 同じテンプレートが未送信であること（再送防止）
- ステータスが won / lost でないこと
- 直近24時間以内に別メールを送信していないこと（乱発防止）

## 停止条件

- リードが opt_out = true に変更された場合
- ステータスが won または lost になった場合
- リードが予約を完了した場合（booked以降はシーケンス停止）

## テンプレート変数

| 変数 | 説明 |
|------|------|
| {{person_name}} | 氏名 |
| {{company_name}} | 会社名 |
| {{booking_url}} | 予約ページURL |
| {{unsubscribe_url}} | 配信停止URL |

## 送信失敗時の処理

1. エラーメッセージを messages テーブルに記録
2. status を 'failed' に設定
3. 次回バッチで再送信を試みる（最大3回）
4. 3回失敗したら手動対応フラグを立てる
